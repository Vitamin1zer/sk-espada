# CLAUDE.md — проект СК «Эспада»

Этот файл читается автоматически в каждой сессии. Держи его в корне репозитория темы.

## Что это за проект

Переезд сайта строительной компании «Эспада» (ремонт квартир, Москва) с Tilda на WordPress. Дизайн готов и зафиксирован в HTML-макетах, задача — точное внедрение, а не переосмысление.

Стек: **WordPress (классическая тема) + SCSS + MDB5 частично + ACF Pro**.

Если макет противоречит документу — прав макет, документ поправить. Если макет противоречит ТЗ — **спросить**, не решать самостоятельно.

## Жёсткие правила

Нарушение любого из них — повод отклонить изменение:

- **`!important` запрещён.** Не применяется стиль — проблема в слое каскада или порядке импорта. Единственное исключение уже сделано в `vendor/_mdb-reset.scss` для Ripple, который инжектит стили в рантайме.
- **Ни одного HEX вне `abstracts/_tokens.scss`.** В компонентах только `var(--c-*)` или `$c-*`. Проверяется stylelint-правилом `color-no-hex`.
- **Вложенность SCSS не глубже трёх уровней.**
- **Радиус 0** у кнопок, полей ввода, форм, попапов, чипов, плашек. Скругления только у карточек (10px) и изображений внутри них (8px).
- **`tel:` без пробелов и скобок** — только `tel:+79938914064`. Вставлять через `espada_phone_link()`.
- **Один `<h1>` на страницу.** Заголовок секции — всегда `h2`.
- **Адреса плоские:** `/design-kvartir/`, не `/design/kvartir/`. Вложенность живёт в дереве админки; крошки строятся по `post_parent`, не по URL.
- **Текст кнопок захвата — только из таблицы CTA** (`04-tokeny.md` §8). Никаких «Отправить» и «Подтвердить» без объекта действия.
- **Тач-цели на мобилке ≥ 44px** по высоте.
- **`@import` в SCSS не использовать** — только `@use` / `@forward`.
- **Сетки на `gap`, не на margin у соседей.** Ряды кнопок, чипов, иконок — всегда flex/grid с `gap`.

## Каскад: как это работает

Порядок слоёв объявлен один раз в `assets/scss/main.scss`:

```scss
@layer reset, vendor, base, layout, components, pages, utilities;
```

Порядок объявления слоёв **сильнее специфичности внутри слоя**. Поэтому `.espada-btn` из слоя `components` перебивает `.btn.btn-primary:not(:disabled):active` из `vendor` — без утяжеления селектора и без `!important`.

Три следствия, которые надо помнить:

1. Правило **вне слоя** сильнее любого слоя. Весь наш CSS обязан лежать в слоях.
2. Inline-стиль сильнее слоёв. В шаблонах inline не писать, кроме подстановки фонового изображения из ACF.
3. `!important` **инвертирует** порядок слоёв. Ещё одна причина им не пользоваться.

## MDB5: что берём

Только каркас, эстетика погашена. Material Design противоречит дизайну этого проекта почти во всём.

**Берём:** Reboot, Grid, Utilities API, и три JS-компонента — Modal, Collapse, Dropdown.
**Не берём:** Buttons, Forms, Cards, Navbar, иконки.
**Выключено:** Ripple, тени, градиенты, скругления.

Если в вёрстке видна «материальность» — приподнятая тень у кнопки, волна при клике, скругление у поля — переопределение не доехало, см. `02-mdb5-i-kaskad.md`.

Классы MDB, за которые цепляется его JS (`modal`, `collapse`, `dropdown-toggle`), оставляем в разметке как есть, а оформление вешаем на параллельные `espada-*`. Классы MDB напрямую не стилизуем.

**CSS Grid из макетов не переписывать на `col-lg-4`.** Конструкция `repeat(auto-fit, minmax(min(100%, 280px), 1fr))` сохраняется целиком: внутренний `min()` не даёт колонке вылезти за контейнер, а `auto-fit` убирает пустоты в рядах — заказчик правил этот дефект дважды.

## Именование

BEM с префиксом: `.espada-header__nav-item--active`.

Префикс обязателен, потому что MDB5 занимает `.btn`, `.card`, `.navbar`, `.form-control`, `.dropdown`, `.accordion`, `.modal`.

Состояния из JS — через `is-` / `has-`: `.is-open`, `.has-error`. Модификаторы из шаблона — через `--`.
