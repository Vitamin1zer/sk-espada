# 02. MDB5 и управление каскадом

## 1. Зачем MDB5 на этом проекте

Честный ответ: библиотека здесь нужна не ради вида, а ради трёх вещей — сетки, утилит и готового JS для модалки, дропдауна и аккордеона. **Визуальный язык проекта противоречит Material Design почти во всём:** нет скруглений, нет теней-эстафет, нет ripple-эффектов, кнопки прямоугольные с трекингом, палитра из одного акцента.

Из этого следует главное решение: **MDB5 подключается частично и с погашенной эстетикой.** Мы берём каркас и выбрасываем оформление. Если на ревью в вёрстке видна «материальность» — приподнятая тень у кнопки, волна при клике, скругление у поля — значит переопределение не доехало.

## 2. Что берём

| Модуль MDB5 | Берём | Зачем |
|---|---|---|
| Reboot | Да | Нормализация, `box-sizing`, сброс полей у заголовков |
| Grid, containers | Да | 12 колонок, `row/col`, гаттеры |
| Utilities API | Да | `d-flex`, `gap-*`, `text-center`, отступы `mt-*` |
| Modal (JS) | Да | Попап заявки: фокус-трап, блокировка скролла, Esc — не переписывать вручную |
| Collapse (JS) | Да | Аккордеоны FAQ и мобильное меню |
| Dropdown (JS) | Да | Фильтры портфолио, клик вне и клавиатура |
| Buttons | Нет | Свой `.espada-btn`, см. §4 |
| Forms / form-outline | Нет | Свои поля: плавающих лейблов в дизайне нет |
| Cards | Нет | Свои карточки, разные радиусы |
| Navbar | Нет | Шапка из двух строк с мега-меню — MDB5 такого не даёт |
| Ripple | **Отключить** | Прямо противоречит дизайну |
| Тени, градиенты | **Отключить** | `$enable-shadows: false`, `$enable-gradients: false` |
| Иконки (Font Awesome) | Нет | Свой SVG-спрайт, иконок в дизайне мало |

Экономия ощутимая: полный MDB5 — около 600 КБ CSS, нужный набор — 40–60 КБ до gzip.

## 3. Точечный импорт

Если ставите через npm (`mdb-ui-kit`), собирайте из исходников только нужное:

```scss
@layer vendor {
  @use 'mdb-ui-kit/src/scss/free/functions';
  @use 'vendor/mdb-variables' as *;      // наши значения — ДО дефолтов
  @use 'mdb-ui-kit/src/scss/free/variables';
  @use 'mdb-ui-kit/src/scss/free/mixins';

  @use 'mdb-ui-kit/src/scss/free/reboot';
  @use 'mdb-ui-kit/src/scss/free/grid';
  @use 'mdb-ui-kit/src/scss/free/utilities/api';

  @use 'vendor/mdb-reset';               // гашение материальности
}
```

JS — тоже точечно, не бандлом:

```js
import { Modal, Collapse, Dropdown } from 'mdb-ui-kit';
// Ripple НЕ импортируем вообще
```

## 4. Переопределение переменных

Файл `vendor/_mdb-variables.scss`. Значения ставятся **до** импорта переменных MDB5, иначе не подхватятся.

```scss
// Палитра
$primary:   #00AD9F;
$secondary: #5C5C5C;
$danger:    #C0392B;
$body-color: #313131;
$body-bg:    #fff;

// Геометрия: скруглений нет нигде, кроме карточек — им радиус даём сами
$border-radius:    0;
$border-radius-sm: 0;
$border-radius-lg: 0;
$border-radius-pill: 0;

// Типографика
$font-family-sans-serif: 'TildaSans', 'Helvetica Neue', Helvetica, sans-serif;
$font-size-base: 0.9375rem;   // 15px — базовый размер body в макетах
$line-height-base: 1.6;
$headings-font-weight: 800;
$headings-line-height: 1.1;

// Гасим материальность
$enable-shadows:   false;
$enable-gradients: false;
$enable-transitions: true;
$enable-rounded:   false;

// Сетка: контейнер контента 1200 при вьюпорте 1440
$grid-gutter-width: 1.5rem;   // 24px
$container-max-widths: (sm: 540px, md: 720px, lg: 960px, xl: 1140px, xxl: 1200px);

// Брейкпоинты — совпадают с нашими, см. 04-tokeny.md §7
$grid-breakpoints: (xs: 0, sm: 576px, md: 768px, lg: 992px, xl: 1200px, xxl: 1400px);
```

## 5. Гашение материальности

Файл `vendor/_mdb-reset.scss`, слой `vendor`. Здесь снимаем то, что библиотека навязывает даже после переопределения переменных.

```scss
// Ripple: если модуль всё же попал в сборку
.ripple-surface,
[data-mdb-ripple-init] {
  &::before, &::after { display: none !important; }
}
// Единственное место, где !important допустим: гасим рантайм-инъекцию плагина.

// Тени, которые MDB5 ставит через свои классы
.shadow-0, .shadow-1-strong, .shadow-2, .shadow-3 { box-shadow: none; }

// Плавающие лейблы форм — в дизайне их нет
.form-outline .form-label { position: static; transform: none; }

// Кнопки: гасим материальные тени и uppercase-логику MDB, свои зададим в компоненте
.btn {
  box-shadow: none;
  text-transform: none;
  &:hover, &:focus, &:active { box-shadow: none; }
}
```

## 6. Почему слои снимают проблему специфичности

Без слоёв разработчик оказывается в знакомой ловушке: MDB5 объявляет `.btn.btn-primary:not(:disabled):not(.disabled):active` — четыре класса и два псевдокласса. Перебить это своим `.espada-btn` невозможно, приходится либо копировать длину селектора, либо ставить `!important`. Через полгода в проекте сотня `!important` и никто не знает, какой из них что держит.

Со слоями порядок объявления сильнее любой специфичности внутри слоя:

```css
@layer vendor, components;

@layer vendor {
  .btn.btn-primary:not(:disabled):active { border-radius: .25rem; }
}
@layer components {
  .espada-btn { border-radius: 0; }   /* выигрывает */
}
```

Правило из одного класса перебивает правило из шести — потому что его слой объявлен позже. Это и есть та каскадность, которую просил заказчик: приоритет задаётся архитектурой один раз, а не спорится в каждом файле.

**Три следствия, которые нужно знать:**

1. Правило **вне слоёв** сильнее любого слоя. Поэтому весь наш код обязан лежать в слоях — иначе случайный незалоенный файл начнёт побеждать всё.
2. Inline-стиль сильнее слоёв. В шаблонах inline не пишем, кроме подстановки фонового изображения из ACF.
3. `!important` **инвертирует** порядок слоёв: важное правило в раннем слое побеждает важное в позднем. Ещё одна причина им не пользоваться — интуиция ломается.

## 7. Как стилизовать компонент, чей JS взят у MDB5

Пример: попап заявки. Разметка нужна MDB-совместимая, чтобы работал его JS, а вид — наш.

```html
<div class="modal fade espada-modal" id="lead-modal" tabindex="-1">
  <div class="modal-dialog espada-modal__dialog">
    <div class="modal-content espada-modal__content">
      …
    </div>
  </div>
</div>
```

Классы MDB (`modal`, `modal-dialog`, `modal-content`) оставляем — за них цепляется скрипт. Оформление вешаем на параллельные `espada-*`. В SCSS не трогаем классы MDB напрямую:

```scss
@layer components {
  .espada-modal {
    &__content {
      border: 0;
      border-radius: 0;
      box-shadow: 0 30px 70px rgb(0 0 0 / 35%);
      padding: $sp-5;
    }
  }
}
```

Так обновление MDB5 не сломает вид, а наши стили не зависят от его внутренней структуры.

## 8. Сетка: где MDB5, а где нет

Сетка библиотеки берётся для простых случаев — две-три равные колонки. Но большая часть раскладок в макетах построена на `repeat(auto-fit, minmax(...))`, и это осознанно: карточки должны перестраиваться сами, без брейкпоинтов.

**Оставляйте CSS Grid из макетов там, где он есть.** Не переписывайте `grid-template-columns: repeat(auto-fit, minmax(min(100%, 280px), 1fr))` на `col-lg-4 col-md-6` — потеряете плавность перестроения и получите пустоты в рядах, которые заказчик уже дважды просил убрать.

Конструкция `minmax(min(100%, 280px), 1fr)` — не украшение: внутренний `min(100%, …)` не даёт колонке вылезти за контейнер на узких экранах. Сохраняйте её целиком.

Правило разделения:

- **CSS Grid** — плитки карточек, кластеры ссылок, тарифы, портфолио, фильтры, сетки этапов.
- **MDB5 grid** — двухколоночные блоки «текст + изображение», где нужны гаттеры библиотеки и вертикальный ритм.
- **Flexbox** — всё внутри карточек и любые ряды кнопок, чипов, иконок. Всегда с `gap`, никогда с margin у соседей.
