# Публикация демо-макетов на GitHub Pages

Задача: выложить эту папку как статический сайт и получить постоянную ссылку для показа клиенту.

## Что это за папка

Статический демо-стенд макетов нового сайта СК «Эспада». Никакой сборки не требуется: это готовые HTML-файлы, которые работают прямо из файловой системы.

- `index.html` — точка входа. Оболочка со списком страниц слева и живым макетом в рамке справа.
- `*.dc.html` — сами макеты, по одному файлу на страницу или группу страниц. Подгружаются в `<iframe>` по клику.
- `support.js` — рантайм, который отрисовывает макеты. Один на все файлы, лежит в корне.
- `assets/` — изображения и шрифты TildaSans.

## Важные особенности

**Имена файлов макетов — на кириллице,** и так и должно остаться. Внутри макетов есть ссылки вида `<dc-import name="Шапка">`, которые ищут файл `Шапка.dc.html` рядом. Переименование в латиницу сломает подключение сквозных компонентов — шапки, подвала, форм и квиза. GitHub Pages отдаёт такие имена корректно, браузер сам кодирует их в URL. Клиент видит только чистый адрес `index.html`, внутренние адреса ему не показываются.

**Никакой сборки, транспиляции и npm.** Не надо запускать бандлеры, минификаторы или сборку ассетов. Любая «оптимизация» здесь только ломает: `support.js` должен остаться как есть, инлайнить его в HTML нельзя.

**React лежит локально, и так должно остаться.** Изначально `support.js` тянул React и ReactDOM с `unpkg.com`, и при недоступном CDN демо открывалось пустой страницей — проверено с отключённым внешним доступом. Библиотеки положены в `assets/vendor/`, а два адреса в `support.js` переписаны на них. Хэши SRI при этом не трогали: файлы побайтово те же, что на unpkg, проверка целостности проходит. Если `support.js` будут обновлять из исходников, эту правку надо повторить, иначе внешняя зависимость вернётся. Ссылка на Babel в коде осталась, но он не загружается — он нужен только в редакторе макетов.

**Ссылки внутри макетов перехватываются оболочкой.** Скрипт в конце `index.html` ловит клики внутри кадра и переводит на соответствующий макет; адреса, которых нет в утверждённой структуре, ведут на `404.dc.html`. Карта соответствий — там же, в начале скрипта. Появится новый макет — добавить его в `FILES`, `PAGES` и при необходимости в `MAP`.

**Регистр имён важен.** Локально на macOS и Windows файловая система регистронезависима, на GitHub Pages — нет. Если решите что-то переименовывать, сверяйте регистр буква в букву.

## Вариант 1 — отдельная ветка `gh-pages` (рекомендуется)

Держит демо отдельно от кода проекта, историю основной ветки не засоряет.

Собираем ветку в отдельном рабочем дереве, чтобы вообще не трогать рабочую копию:

```bash
# из корня репозитория
git worktree add --orphan -b gh-pages /tmp/ghpages   # пустое дерево, main не затронут
cd /tmp/ghpages
cp -r /путь/к/publish/. .         # содержимое папки, не саму папку
rm -f DEPLOY.md                   # инструкция внутренняя, публиковать её не нужно
git add -A
git commit -m "Демо макетов для показа клиенту"
git push -u origin gh-pages
cd -
git worktree remove /tmp/ghpages
```

Ветка уже существует — тогда `git worktree add /tmp/ghpages gh-pages`, вычистить
всё кроме `.git` и скопировать заново.

> **Не делайте `git rm -rf .` в рабочей копии.** Эта команда удаляет файлы
> и с диска, а не только из индекса: следом `git add -A` затянет в демо-ветку
> весь проект, включая паспорт с доступами. Отдельное рабочее дерево снимает
> оба риска.

Дальше в интерфейсе GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `gh-pages` / `(root)` → Save.**

Через одну-две минуты ссылка будет здесь же, на странице Pages. Формат: `https://<owner>.github.io/<repo>/`

## Вариант 2 — папка `docs/` в основной ветке

Проще в обслуживании, если демо будете часто обновлять.

```bash
mkdir -p docs
cp -r /путь/к/publish/. docs/
touch docs/.nojekyll
git add docs
git commit -m "Демо макетов для показа клиенту"
git push
```

Настройки: **Settings → Pages → Source: Deploy from a branch → Branch: `main` / `/docs` → Save.**

## Файл `.nojekyll` — не забыть

Без него GitHub прогоняет папку через Jekyll, и тот игнорирует всё, что начинается с подчёркивания, а иногда ломается на нелатинских именах. Пустой файл `.nojekyll` в корне публикуемой папки полностью отключает эту обработку. Один из самых частых поводов, по которому Pages отдаёт 404 на существующий файл.

## Проверка после публикации

1. Корневая ссылка открывается, слева виден список из 15 страниц.
2. Клик по «Главная» — в рамке появляется страница с обложкой и фотографиями. Если рамка пустая, значит не создан `.nojekyll` либо перепутан регистр в имени файла.
3. Внутри рамки нет своих полос прокрутки: кадр подгоняется под высоту макета, страница листается целиком. На узком окне артборд ужимается по ширине, горизонтальной прокрутки быть не должно.
4. Клик по пункту мега-меню внутри макета открывает соответствующую страницу, а «В рассрочку» или «Цены» — макет 404.
5. Внутри макетов должно работать: раскрытие мега-меню по наведению, табы тарифов, аккордеоны вопросов, шаги квиза с пересчётом суммы, дропдауны фильтров портфолио.

## Если репозиторий приватный

GitHub Pages на приватных репозиториях доступен только на платных тарифах. Варианты: сделать репозиторий публичным (в демо нет ничего секретного, только макеты и фотографии с текущего сайта), либо выложить через Netlify Drop — `app.netlify.com/drop`, перетащить папку, ссылка появляется сразу.

## Обновление демо

Макеты правятся в основном проекте, затем папка `publish` пересобирается целиком и заливается поверх. Ссылка при этом не меняется — клиенту повторно её отправлять не нужно.
