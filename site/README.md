# Код сайта sk-espada.ru

Один код на два окружения. Продакшен и тестовый поддомен собираются из одних
и тех же файлов, различия живут только в конфигах `env/`. Так стейдж всегда
совпадает с продом, и правку не приходится делать дважды.

| Окружение | Домен | Индексация |
|---|---|---|
| production | sk-espada.ru | открыта |
| staging | dev.sk-espada.ru | закрыта тремя способами |

## Что где лежит

```
site/
├── wp-content/
│   ├── themes/espada/     тема проекта, собирается по макетам из other/Макеты
│   ├── plugins/           только свои плагины, сторонние ставятся отдельно
│   └── mu-plugins/        обязательные плагины, включаются без администратора
├── acf-json/              экспорт групп полей ACF, восстанавливает админку из файлов
├── import/                pages.csv, скрипт импорта, карта редиректов
├── env/                   конфиги окружений, реальные значения не в git
└── deploy/                выкладка на прод и на стейдж
```

Ядро WordPress, сторонние плагины и загрузки пользователей в репозиторий
не попадают: ядро ставится менеджером пакетов, аплоады живут на сервере
и синхронизируются отдельно.

## Порядок разработки

1. Правка делается локально, коммитится в репозиторий.
2. Выкладывается на `dev.sk-espada.ru` и проверяется там.
3. После приёмки выкладывается на `sk-espada.ru`.

Правок на продакшене мимо репозитория не бывает: следующая выкладка их затрёт.

## Импорт контента

Контракт между таблицей и импортом описан в скилле переноса на WordPress.
Ключевое, что проверять каждый раз:

- поле ACF типа «изображение» требует ID вложения, а не URL, иначе в базу
  запишется ноль и картинки молча пропадут;
- транслитерация слагов плагином при программном создании записи не работает,
  транслитерировать нужно в самом скрипте;
- импорт идёт по уровням вложенности: родители раньше детей.

Любой скрипт импорта работает в два прохода: без ключа показывает план
(«создам столько-то, обновлю столько-то, пропущу с причинами»), с ключом
`--apply` применяет. Перед применением снимается дамп базы.

## Стейдж и индексация

Открытый тестовый поддомен — это полная копия сайта в индексе, которая
конкурирует с боевым доменом. Закрываем сразу тремя способами, потому что
каждый по отдельности иногда не срабатывает:

1. `BLOG_PUBLIC=0` в `staging.env` — WordPress отдаёт noindex в шаблонах.
2. `robots.txt` на стейдже с `Disallow: /`.
3. HTTP-авторизация на уровне сервера — самый надёжный барьер.

Перед выкладкой на прод проверять, что эти настройки не уехали вместе с кодом.
