# Выкладка

Два окружения собираются из одного кода, различия — только в конфиге.
Порядок всегда один: сначала стейдж, после приёмки продакшен.

## Что выкладывается

Из репозитория на сервер уезжает содержимое `site/wp-content` и `site/acf-json`.
Ядро WordPress, сторонние плагины и папка `uploads` живут на сервере
и деплоем не трогаются.

## Порядок

1. Правка коммитится в репозиторий.
2. Выкладка на `dev.sk-espada.ru`, проверка там.
3. После приёмки выкладка на `sk-espada.ru`.

Правок на продакшене мимо репозитория не бывает: следующая выкладка их затрёт.

## Перед каждой выкладкой на продакшен

- [ ] снят дамп базы, команда отката записана рядом с дампом
- [ ] на стейдже проверено то же самое изменение
- [ ] `BLOG_PUBLIC=1` в конфиге продакшена
- [ ] `robots.txt` продакшена не содержит `Disallow: /`
- [ ] счётчик Метрики 108523185 на месте

## Перед каждой выкладкой на стейдж

- [ ] `BLOG_PUBLIC=0` в конфиге стейджа
- [ ] `robots.txt` стейджа отдаёт `Disallow: /`
- [ ] HTTP-авторизация на поддомене включена
- [ ] счётчик Метрики на стейдже отключён, чтобы не пачкать статистику

## robots.txt

Файл различается по окружениям и не должен уезжать со стейджа на прод.
Держим два файла и подкладываем нужный при выкладке.

**Продакшен:**

```
User-agent: *
Allow: /
Sitemap: https://sk-espada.ru/sitemap.xml
```

**Стейдж:**

```
User-agent: *
Disallow: /
```

## Откат

Дамп базы снимается до каждого применения, имя файла с датой. Откат должен
быть одной командой, и она пишется в лог рядом с дампом. Код откатывается
переключением на предыдущий коммит и повторной выкладкой.

## Что ещё не решено

Способ выкладки зависит от хостинга, которого пока нет. Когда появится доступ,
сюда добавится конкретика: rsync по SSH, git pull на сервере или деплой
через GitHub Actions. До этого раздел остаётся описанием порядка, а не
инструкцией с командами.
