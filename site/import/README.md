# Импорт контента

Здесь живёт таблица `pages.csv` и скрипт, который заливает её в WordPress.
Таблица — контракт между SEO-специалистом и импортом: специалист заполняет
её руками, импорт грузит без ручной работы.

## Откуда берётся содержимое

- адреса, названия и статусы страниц — из
  `other/Семантика и структура/СТРУКТУРА САЙТА _ СК ЭСПАДА _ SEO VICTORY.xlsx`,
  лист «Структура сайта»;
- мета-теги — из того же файла, лист «Мета-теги»;
- тексты и картинки старого сайта — из `other/Выгрузка сайта с Тильды/`,
  адрес источника по каждой странице лежит в колонке `otkuda`.

## Колонки

**Обязательные.** Строка без любой из них пропускается с предупреждением.

| Колонка | Что это |
|---|---|
| `post_title` | Название страницы в админке |
| `post_name` | Слаг латиницей |

**Служебные.**

| Колонка | Что это |
|---|---|
| `otkuda` | Адрес страницы-источника на старом сайте, для сверки после импорта |
| `zzz` | «Существует» — обновить по слагу, «Создать» — создать новую |

**Стандартные поля WordPress:** `post_content`, `parent_page_slug`,
`page_template`.

**Мета-теги:** `meta_title`, `meta_description`, `page_h1`.

**Поля ACF:** по колонке на поле, имя колонки равно имени поля. Повторители
и вложенные группы — одной колонкой `page_meta` с JSON-массивом пар
`{"key": ..., "value": ...}`, повторяющийся ключ означает следующий ряд.

## Правила

1. Одна строка — одна страница. Дубли слагов внутри файла останавливают строку.
2. Пустая ячейка означает «не трогать» при обновлении и «оставить пустым»
   при создании. Затирать поле пустым значением импорт не должен.
3. Файл версионируется вместе со скриптом: какой CSV — такой и прогон.

## Как работает импорт

1. Сначала восстанавливаются группы полей ACF из `../acf-json`, потом грузится
   контент. Иначе поля некуда писать.
2. CSV читается, проверяется на обязательные колонки.
3. Строится дерево по `parent_page_slug`, импорт идёт по уровням: родители
   раньше детей.
4. По каждой строке пишется отчёт: создано, обновлено или пропущено с причиной.

**Два прохода обязательны.** Без ключа скрипт показывает план: сколько создаст,
сколько обновит, что пропустит и почему. С ключом `--apply` применяет.
Применение без показанного плана запрещено, перед ним снимается дамп базы.

## Грабли, которые уже стоили пересборки

- Поле ACF типа «изображение» требует **ID вложения, а не URL**. При URL
  в базу пишется ноль, и картинки молча пропадают.
- Транслитерация слагов плагином при `wp_insert_post` не срабатывает —
  транслитерировать нужно в самом скрипте.
- Иерархические адреса таксономий WordPress разбирает только по последнему
  сегменту, поэтому вложенность делается плоскими уникальными слагами.
- `filemtime()` на отсутствующем файле печатает предупреждение прямо в вёрстку,
  вызов оборачивается проверкой существования.

## После импорта

- обойти все созданные адреса, каждый должен отвечать 200;
- у каждой страницы есть H1 и description;
- выборочно сверить контент со старым сайтом по колонке `otkuda`;
- отправить формы и убедиться, что заявки приходят.

## Карта редиректов

Со старого сайта переезжают четыре адреса:

| Было | Стало |
|---|---|
| `/komplekt` | `/komplektaciya/` |
| `/partners` | `/partneram/` |
| `/politicakonfident` | `/politika-konfidencialnosti/` |
| `/soglasienaobrabotku` | `/soglasie-na-obrabotku/` |

`/design` и `/priemka` сохраняют адреса, у них меняется только завершающий
слеш. Главная остаётся на `/`, но меняет роль: становится страницей о всём
комплексе услуг, а ремонт уезжает на `/remont-kvartir/`.

Отдельно нужен редирект со всех адресов с `www` на версию без него
и с `http` на `https`: сейчас сайт доступен по обеим версиям сразу.
